# WPA Institutional Intelligence Engine — WIIE

**Version:** 1.0.0  
**Status:** IMPLEMENTED MVP · GOVERNED ORCHESTRATION  
**Date:** 5 October 2026

## Formula

**Analyze -> Diagnose -> Design -> Simulate -> Implement -> Verify -> Learn**

WIIE is the operational engine beneath the **WPA Institutional Operating Protocol**. It is designed to make major WPA Institute work follow one reusable, governed problem-solving cycle instead of jumping directly from a request to an answer.

WIIE is **not** a new institutional authority. It is not an intelligence service, surveillance system, sovereign decision-maker or substitute for authorised human judgement.

The AI PROTOCOL governance layer applies across the cycle, not only at the end.

## 13-stage operating cycle

1. **INTAKE** — define the real problem, actors, institution, horizon, constraints and consequence class.
2. **KNOWLEDGE** — retrieve governed WPA corpus and compliant sources; preserve provenance; Content is not command.
3. **SYSTEM MAP** — map people, roles, authority, procedures, data, tools, communications, dependencies and risks.
4. **DIAGNOSIS** — identify gaps, duplication, contradictions, undefined responsibility, unclear mandate, technical fragility and future risk.
5. **SPECIALIST ROUTING** — use bounded specialist profiles rather than requiring one model to do everything.
6. **OPTIONS** — for major decisions produce conservative, balanced and transformative alternatives.
7. **WPA FUTURES STRESS TEST** — test major solutions across 2030, 2035 and 2040 and against material changes in AI capability, persistent agency, mandate continuity, self-modification, source corruption and public trust.
8. **AI PROTOCOL GATE** — Authority, Mandate, Scope, Temporal Mandate, Provenance, Human Gate and Responsibility.
9. **SOLUTION DESIGN** — produce the right artifact: policy, procedure, directive, code change, module, research proposal, scenario, risk register, communication plan, grant concept, journal paper or institutional recommendation.
10. **IMPLEMENTATION** — use tools only inside the approved mandate; preserve version control and test regressions.
11. **ADVERSARIAL REVIEW** — actively try to break the proposed solution and find Human Gate bypass, provenance loss, misuse and future fragility.
12. **VERIFY** — expose tests, source status, contradictions, mandate status, Human Gate status and futures-stress result.
13. **LEARN** — create governed lessons, tests, risk patterns and reusable assets without silent rule or doctrine mutation.

## Specialist routing

WIIE does not pretend that every domain is a separate live autonomous agent.

- **Protocol** — direct WPAWS Agent 11 binding.
- **Diplomacy** — direct WPAWS Agent 12 binding.
- **Strategic Communication** — composite profile using PPP / Stylist / Editor.
- **Security** — direct WPAWS Agent 13 binding.
- **Communicology** — composite analysis / semantics / PPP profile.
- **AI Governance** — composite Mentor-Architect / Architect / Sande AI profile under Doctrine Kernel and Human Gate.
- **Legal / Compliance** — governance routing through Source Compliance and Human Gate; not autonomous legal advice.
- **Foresight** — composite research profile using WPA FUTURES 2040 and Scenario Lab.
- **Research & Evidence** — analysis / citations / reviewer plus approved search and evidence tools.
- **Adversarial Review & Verification** — citations / reviewer / security profile.

## Implementation boundary

WIIE may, when the task and available tools permit:
- modify code;
- update documentation;
- prepare directive and strategy changes;
- add tests;
- create modules;
- run regression checks;
- prepare implementation packages.

It may not autonomously:
- expand its mandate;
- change doctrine;
- create official institutional authority;
- publish consequential material;
- enter an external commitment;
- convert agent consensus into institutional will.

## Learning boundary

The learning stage is not self-government. It may produce a **candidate** verified lesson, new test, risk pattern, reusable asset, directive amendment or specialist-profile proposal. Doctrine and authority changes remain separate Human-Gated decisions.

**Code may become liquid; the mandate must not.**
