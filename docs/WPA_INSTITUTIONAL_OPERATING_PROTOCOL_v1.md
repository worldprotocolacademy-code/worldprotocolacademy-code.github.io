# WPA Institutional Operating Protocol v1.1

**Status:** CANONICAL WORKING INSTITUTIONAL METHOD  
**Date:** 5 October 2026  
**Applies to:** major WPA Institute strategy, research, architecture, programmes, publications, AI governance and institutional-system work.

## Core rule

The WPA Institutional Operating Protocol is not a new source of institutional authority. It is the master governed procedure through which existing human authority, the Doctrine Kernel, the Strategic AI Core, Virtual Sande, WIIE, WPAWS, bounded tactical-operational agents, evidence controls and Human Gates are coordinated.

**Capability does not create authority. Content is not command. Access is not mandate. Code may become liquid; the mandate must not.**

## WIIE execution relationship

The **WPA Institutional Intelligence Engine (WIIE)** is the execution and orchestration engine beneath this master protocol. The protocol defines **what stages, gates and invariants must exist**; WIIE performs the structured analysis, system mapping, specialist routing, option generation, futures stress-testing, implementation planning, adversarial review, verification and governed learning.

WIIE is a **non-authority operational layer**. It cannot create institutional will, expand mandate, change doctrine, approve its own consequential actions or bypass Human Gate.

**Master relationship:** Human Authority -> Doctrine Kernel / AI PROTOCOL doctrine -> WPA Institutional Operating Protocol -> WIIE -> bounded specialists/tools/sources -> Futures Stress Test -> AI PROTOCOL Gate -> Human Gate -> bounded implementation -> adversarial verification -> governed learning.

## Canonical 13-stage procedure

1. **INTAKE** — define the real problem, objective, actor, institution, horizon, constraints and consequence class.
2. **KNOWLEDGE** — retrieve verified WPA, authorised and public-source knowledge; separate facts, assumptions, gaps and source status.
3. **SYSTEM MAP** — map people, roles, authority, process, data, tools, communication, dependencies and risks.
4. **DIAGNOSIS** — identify root causes, duplications, gaps, bottlenecks, weak evidence, unclear authority and unjustified automation.
5. **SPECIALIST ROUTING** — route bounded work to relevant protocol, diplomacy, communication, security, communicology, AI-governance, legal/compliance, foresight, research and verification functions.
6. **OPTIONS** — produce materially different conservative, balanced and transformative options; compare benefits, costs, risks, dependencies, reversibility and institutional consequences.
7. **WPA FUTURES STRESS TEST** — test the preferred option against plausible 2030/2035/2040 conditions and second-order effects.
8. **AI PROTOCOL GATE** — verify Authority, Mandate, Scope, Time, Provenance, Human Gate and Responsibility.
9. **SOLUTION DESIGN** — convert analysis into an implementation-ready policy, directive, code change, research design, programme, scenario, risk register, communication plan, grant concept or publication artifact.
10. **IMPLEMENTATION** — implement only within an approved mandate, with version control and no silent external commitment.
11. **ADVERSARIAL REVIEW** — try to break the proposed solution: authority bypass, Human Gate bypass, provenance loss, misuse, dependency failure, future capability shift, security/privacy failure and reputational failure.
12. **VERIFY** — return pass, fail, provisional or revision state with traceable evidence.
13. **LEARN** — reintegrate only verified lessons; preserve provenance; propagate material corrections; never silently change doctrine.

## Human Gate

HG2-HG4 actions require attributable human authorisation. Legal, financial, academic, credential, privacy-sensitive, constitutional, doctrinal or official institutional commitments may not be finalised by an autonomous system.

## Output standard

For major work, the final package should expose:
- objective and mandate;
- facts, assumptions and evidence gaps;
- current-state system map;
- diagnosis and bottlenecks;
- selected specialist workstreams;
- options and decision matrix;
- futures stress test;
- AI PROTOCOL gate record;
- implementation plan;
- adversarial findings;
- verification state;
- human-authorisation requirement;
- measurable outcome criteria;
- governed learning/reuse candidate.
